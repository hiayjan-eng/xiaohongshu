# V0.1 Phase 2 用户真实验收指南

## 测试入口

- Preview Web：`https://xiaohongshu-git-v01-core-library-release-ayj.vercel.app`
- 扩展版本：`0.2.5-preview`（manifest 显示 0.2.5，popup profile 显示 Preview 测试包 0.2.5-preview）
- 解压加载目录：`release-artifacts/extension-beta-preview-v0.2.5/`
- ZIP：`release-artifacts/collection-revival-extension-beta-preview-v0.2.5.zip`

请在 Chrome“管理扩展程序”打开开发者模式，使用“加载已解压的扩展程序”选择上述目录。确认 popup 顶部显示 Preview 0.2.5-preview，并且 Web 地址是本指南的 Preview 分支别名；不要在 Production 验收。

## 最少验收步骤

### 1. 20 条：暂停、popup 恢复、重复导入

1. 打开本人小红书主页的“收藏”标签，选择 20 条开始扫描。
2. 出现若干条后点击暂停，确认页面不再滚动、发现数量不再增长。
3. 关闭 popup，再次打开，确认目标、数量、选择和暂停状态恢复。
4. 点击继续，完成到目标；记录发现、有效、重复、无链接、失败和过滤数。
5. 导入 Preview Web，记录首次新增数量；不改原始数据，再导入同一批，确认第二次新增为 0，重复显示“已存在”。

### 2. 100 条：扩展 reload 恢复

1. 选择 100 条开始扫描，中途暂停并记下发现数量。
2. 在 Chrome 扩展管理页对 0.2.5-preview 点击“重新加载”，回到同一收藏页并重新打开 popup。
3. 确认 target=100、已发现数量和勾选状态恢复，点击继续完成。
4. 记录开始/完成时间和所有计数；不要记录标题、作者或完整链接。

### 3. 200 条：连续稳定性

1. 选择 200 条开始扫描，至少做一次暂停/继续；可关闭 popup 后再打开。
2. 完成后核对 target、有效数和进度一致，页面受限或验证码时扩展应停止并明确提示，不能绕过。
3. 导入一次并再次导入相同批次，确认第二次新增为 0。

### 4. 20 条原帖

1. 从真实导入结果随机选 20 条，在收藏池、专辑或搜索结果点击“原帖”，只记录脱敏 hash 与“成功 / 删除 / 不可见 / 错误跳转”。
2. 对打不开的一条在详情页点击“标记原帖失效”，确认出现“原帖可能已删除、不可见或链接已失效”。
3. 点击“修复链接”，粘贴可打开的具体笔记 URL，刷新详情页；确认仍能打开，且导出本地数据时 raw sourceUrl 未被替换、userCorrectedSourceUrl 单独保存。
4. 20 条有效链接至少 19 条正确打开，才满足 ≥95% 发布门。

### 5. 数据诊断

打开 Preview Web 的“设置”，查看“数据完整性诊断”，只回填十项数量和错误类型汇总。不要复制错误对应的标题、正文、作者、完整 URL、sourceId、token 或用户 ID。

## 回填格式

请把以下两组脱敏结果发回本任务：

1. 20 / 100 / 200 三行统计：目标、开始/完成时间、发现、有效、重复、无链接、失败、是否暂停继续、popup 恢复、扩展 reload 恢复、首次新增、重复导入新增。
2. 20 条原帖汇总：成功/删除/不可见/错误跳转数量、失效提示是否出现、修复入口是否成功、刷新是否保留、raw sourceUrl 是否未覆盖。

收到结果后只能做两件事之一：将 Phase 2 评为 PASS，或修复具体 Phase 2 Blocking；不会进入分类、专辑、搜索、行动卡、迁移或 Production。
